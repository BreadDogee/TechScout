## Как мы работаем

Нас трое, поэтому полный набор церемоний Scrum не нужен: он съест время, которого и так мало. Мы работаем **по облегчённому Scrum**:

- спринт — 2 недели и совпадает с парой модулей курса; цель спринта — сдать соответствующую часть лабораторной;
- бэклог и спринты ведутся в Jira (Scrum-проект с ключом `SCRUM`), чтобы видеть план и скорость;
- из событий Scrum оставляем планирование, обзор и ретроспективу; ежедневная встреча заменена коротким письменным обменом статусом и одной голосовой синхронизацией в неделю.

## Статусы задач в Jira

| Статус | Значение |
|---|---|
| Idea | Задачу нужно уточнить: не выполнено определение готовности |
| К выполнению | Задача готова к работе |
| В работе | Задача выполняется |
| Тестирование | Результат на ревью и проверке |
| Готово | Выполнено определение завершённости |

## Как принимаем решения

- Решения по продукту и архитектуре обсуждаем втроём и фиксируем письменно в документах и `CHANGELOG.md`.
- При разногласии сравниваем варианты по ценности для пользователя, трудоёмкости и риску. Если за 15 минут не договорились — решает большинство; спорные вопросы по требованиям курса выносим преподавателю.
- Любое решение, которое трудно откатить, записывается; с модуля 05 — в формате архитектурного решения.
- Изменение MVP, границ объёма или сроков — только через запрос на слияние с ревью двух других участников.

## Определение готовности

Задачу можно брать в работу, если:

- [ ] указано, какой истории с карты или какой части лабораторной она соответствует;
- [ ] описан ожидаемый результат: какой файл, раздел или поведение появится;
- [ ] с ЛР 2А — есть критерии приёмки в формате «Дано — Когда — Тогда»;
- [ ] понятно, каким изменением в интерфейсе, API или документе она проявится;
- [ ] нет незакрытых вопросов к формулировке и внешних блокировок;
- [ ] задача оценена и помещается в одну неделю; если нет — разбита.

## Определение завершённости

Задача считается сделанной, если:

- [ ] изменение влито в `main` через запрос на слияние;
- [ ] запрос прошёл ревью другого участника, есть минимум один содержательный комментарий с меткой типа;
- [ ] конвейер проверок зелёный;
- [ ] написаны тесты на критерии приёмки, и они проходят (с модуля 07; для документов — проверки конвейера);
- [ ] обновлена документация: README или соответствующий файл в `docs/`;
- [ ] добавлена запись в `docs/CHANGELOG.md`;
- [ ] изменение проверено на чистом окружении, а не только «у меня работает»;
- [ ] задача в Jira переведена в «Готово».

**Как ревьюер проверяет «документация обновлена»:** в запросе на слияние есть изменённый файл в `docs/` или README, относящийся к задаче, либо в описании запроса явно написано, почему документация не меняется.

## Инструменты

| Назначение | Инструмент | Правило |
|---|---|---|
| Бэклог и спринты | Jira, Scrum-проект `SCRUM` | У задачи есть исполнитель, оценка, спринт; ключ задачи — в названии ветки и запроса |
| Карты (CJM, USM) | holst.so или Miro | Экспорт в PNG в `docs/images/`; текстовая версия — в Markdown |
| Диаграммы | Mermaid прямо в Markdown | Версионируются вместе с текстом |
| Документы | Markdown в `docs/` | Обязательно |
| Код и ревью | GitHub | Только через запросы на слияние |
| Связь | Общий чат | Важные решения переносятся в документы |
